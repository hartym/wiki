Four Rust web frameworks side by side: Actix Web, Axum, Rocket and Poem. Versions, release dates
and star counts are a snapshot taken on 2026-08-05 from crates.io and GitHub.

The crate names and module paths below were checked against crates.io and docs.rs. The code
snippets were not compiled; they are being reviewed one framework at a time. Treat them as shape,
not as copy-paste material.

## Actix Web

[Actix Web](https://actix.rs/) has the deepest set of ready-made middleware of the four. Despite
the name it no longer runs on the Actix actor framework: version 4 is a plain Tokio application,
and the last piece that still needed actors (`actix-web-actors`, for WebSockets) is deprecated in
favour of [actix-ws](https://crates.io/crates/actix-ws).

### Status

- Latest release 4.14.0 (2026-06-21). The 4.x line has been stable since 4.0.0 (2022-02-25).
- [actix/actix-web](https://github.com/actix/actix-web), about 24.8k stars, Apache-2.0.
- Minimum supported Rust version: 1.88.

### Hello World Example

```rust
use actix_web::{web, App, HttpServer, Result};
use serde::{Deserialize, Serialize};

#[derive(Serialize)]
struct HelloResponse {
    message: String,
}

#[derive(Deserialize)]
struct HelloQuery {
    name: Option<String>,
}

async fn hello(query: web::Query<HelloQuery>) -> Result<web::Json<HelloResponse>> {
    let name = query.name.as_deref().unwrap_or("World");
    Ok(web::Json(HelloResponse {
        message: format!("Hello, {}!", name),
    }))
}

#[actix_web::main]
async fn main() -> std::io::Result<()> {
    println!("Starting server at http://localhost:8080");

    HttpServer::new(|| {
        App::new()
            .route("/hello", web::get().to(hello))
    })
    .bind("127.0.0.1:8080")?
    .run()
    .await
}

// Usage:
// GET /hello -> {"message": "Hello, World!"}
// GET /hello?name=Alice -> {"message": "Hello, Alice!"}
```

### Ecosystem

| Need | Crates | Notes |
|---|---|---|
| OAuth2 | `oauth2` | Generic client, nothing Actix-specific required. |
| JWT | `actix-web-httpauth`, `jsonwebtoken` | Bearer extractor, then token validation. |
| Rate limiting | `actix-governor` | `actix-ratelimit` is dead, last release January 2021. |
| RBAC | `actix-casbin-auth` | Casbin middleware. `actix-casbin` is the storage adapter, not the middleware. |
| CORS | `actix-cors` | Official. |
| Sessions | `actix-session` | Cookie and Redis stores. |
| WebSockets | `actix-ws` | Replaces the deprecated `actix-web-actors`. |
| SSE | `actix-web-lab` | `sse` module. |
| GraphQL | `async-graphql`, `juniper` | |
| OpenAPI | `utoipa`, `paperclip` | |
| Metrics | `actix-web-prom` | Prometheus exporter. |
| Tracing | `tracing-actix-web` | |

## Axum

[Axum](https://github.com/tokio-rs/axum) is built by the Tokio team on top of Tower, so its
middleware are plain Tower layers shared with the rest of that ecosystem (`tower-http`, `tonic`).
No routing macros: handlers are ordinary async functions, and what they may take as arguments is
decided by traits.

### Status

- Latest release 0.8.9 (2026-04-14).
- Still `0.x`, and minor bumps are breaking: 0.7 (2023-11-27), 0.8 (2025-01-01). Budget a
  migration at each one.
- [tokio-rs/axum](https://github.com/tokio-rs/axum), about 26.8k stars, MIT.

### Hello World Example

```rust
use axum::{
    extract::Query,
    response::Json,
    routing::get,
    Router,
};
use serde::{Deserialize, Serialize};

#[derive(Serialize)]
struct HelloResponse {
    message: String,
}

#[derive(Deserialize)]
struct HelloParams {
    name: Option<String>,
}

async fn hello(Query(params): Query<HelloParams>) -> Json<HelloResponse> {
    let name = params.name.as_deref().unwrap_or("World");
    Json(HelloResponse {
        message: format!("Hello, {}!", name),
    })
}

#[tokio::main]
async fn main() {
    let app = Router::new()
        .route("/hello", get(hello));

    println!("Starting server at http://localhost:8080");

    let listener = tokio::net::TcpListener::bind("127.0.0.1:8080")
        .await
        .unwrap();

    axum::serve(listener, app).await.unwrap();
}

// Usage:
// GET /hello -> {"message": "Hello, World!"}
// GET /hello?name=Bob -> {"message": "Hello, Bob!"}
```

### Ecosystem

| Need | Crates | Notes |
|---|---|---|
| OAuth2 | `oauth2`, `axum-login` | |
| JWT | `jsonwebtoken`, `axum-auth` | |
| Rate limiting | `tower-governor` | Tower layer, works outside Axum too. |
| RBAC | `axum-casbin` | |
| CORS | `tower-http` | `cors` feature. |
| Sessions | `tower-sessions` | Replaces `axum-sessions`, unmaintained since 2023. |
| WebSockets | built in | `axum::extract::ws`. |
| SSE | built in | `axum::response::sse`. |
| GraphQL | `async-graphql` | |
| OpenAPI | `utoipa`, `aide` | |
| Metrics and tracing | `tower-http`, `tracing` | Trace layer plus the usual `tracing` subscribers. |
| gRPC | `tonic` | Same Tower stack, so an Axum router and a Tonic service can share a port. |

### Additional Examples

#### JWT Authentication Layer

```rust
use axum::{
    middleware::{self, Next},
    response::Response,
    extract::Request,
};
use jsonwebtoken::{decode, DecodingKey, Validation};

async fn auth_middleware(
    mut req: Request,
    next: Next,
) -> Result<Response, StatusCode> {
    let token = req.headers()
        .get("Authorization")
        .and_then(|v| v.to_str().ok())
        .and_then(|v| v.strip_prefix("Bearer "));

    match token {
        Some(token) => {
            // Validate JWT
            let decoded = decode::<Claims>(
                token,
                &DecodingKey::from_secret(b"secret"),
                &Validation::default()
            ).map_err(|_| StatusCode::UNAUTHORIZED)?;

            req.extensions_mut().insert(decoded.claims);
            Ok(next.run(req).await)
        }
        None => Err(StatusCode::UNAUTHORIZED)
    }
}

let app = Router::new()
    .route("/protected", get(protected_handler))
    .layer(middleware::from_fn(auth_middleware));
```

#### Rate Limiting with Tower Governor

```rust
use tower_governor::{governor::GovernorConfigBuilder, GovernorLayer};

let governor_conf = GovernorConfigBuilder::default()
    .per_second(2)
    .burst_size(10)
    .finish()
    .unwrap();

let app = Router::new()
    .route("/api/limited", get(handler))
    .layer(GovernorLayer {
        config: governor_conf,
    });
```

## Rocket

[Rocket](https://rocket.rs/) trades explicitness for ergonomics: routes are attribute macros,
request validation goes through guards (types implementing `FromRequest`), and configuration,
forms and templating ship in the box. It is also the slowest moving of the four.

### Status

- Latest release 0.5.1 (2024-05-23). Before that: 0.5.0 (2023-11-17), and the previous major
  0.4.0 dates from December 2018. Still pre-1.0.
- [rwf2/Rocket](https://github.com/rwf2/Rocket), about 25.8k stars. The repository moved from
  Sergio Benitez's account to the RWF2 organisation; last commit December 2025.
- Async since 0.5, on Tokio.

### Hello World Example

```rust
#[macro_use] extern crate rocket;
use rocket::serde::{Serialize, json::Json};

#[derive(Serialize)]
#[serde(crate = "rocket::serde")]
struct HelloResponse {
    message: String,
}

#[get("/hello?<name>")]
fn hello(name: Option<String>) -> Json<HelloResponse> {
    let name = name.as_deref().unwrap_or("World");
    Json(HelloResponse {
        message: format!("Hello, {}!", name),
    })
}

#[launch]
fn rocket() -> _ {
    println!("Starting server at http://localhost:8080");
    rocket::build()
        .mount("/", routes![hello])
}

// Usage:
// GET /hello -> {"message": "Hello, World!"}
// GET /hello?name=Charlie -> {"message": "Hello, Charlie!"}
```

### Ecosystem

| Need | Crates | Notes |
|---|---|---|
| OAuth2 | `rocket_oauth2` | |
| JWT | `jsonwebtoken` in a request guard | `rocket_jwt` exists but has not moved since December 2023. |
| Rate limiting | none | No maintained crate. Write a fairing. |
| RBAC | request guards | The guard pattern covers this cleanly, no crate needed. |
| CORS | `rocket_cors` | |
| Sessions | `rocket_session` | Small crate, few users. |
| WebSockets | `rocket_ws` | |
| SSE | built in | `rocket::response::stream::EventStream`. |
| GraphQL | `juniper_rocket`, `async-graphql` | |
| OpenAPI | `rocket_okapi` | |
| Metrics | `rocket_prometheus` | |
| Templates | `rocket_dyn_templates` | Handlebars and Tera. |
| Static files | built in | `rocket::fs::FileServer`. |
| Forms | built in | The strongest form and multipart handling of the four. |

### Additional Examples

#### JWT Authentication Guard

```rust
use rocket::request::{self, Request, FromRequest};
use rocket::outcome::Outcome;

pub struct User {
    pub id: String,
    pub role: String,
}

#[rocket::async_trait]
impl<'r> FromRequest<'r> for User {
    type Error = &'static str;

    async fn from_request(req: &'r Request<'_>) -> request::Outcome<Self, Self::Error> {
        let token = req.headers()
            .get_one("Authorization")
            .and_then(|v| v.strip_prefix("Bearer "));

        match token {
            Some(token) => {
                // Validate JWT and extract user
                match validate_jwt(token) {
                    Ok(user) => Outcome::Success(user),
                    Err(_) => Outcome::Error((Status::Unauthorized, "Invalid token"))
                }
            }
            None => Outcome::Error((Status::Unauthorized, "Missing token"))
        }
    }
}

#[get("/protected")]
fn protected_route(user: User) -> Json<Value> {
    Json(json!({ "user_id": user.id }))
}
```

## Poem

[Poem](https://github.com/poem-web/poem) is the smallest of the four and the most API-first:
`poem-openapi` derives the OpenAPI document from your types, which is its main reason to exist.
Development on GitHub is active but releases are rare.

### Status

- Latest release: `poem` 3.1.12 and `poem-openapi` 5.1.16, both 2025-07-28. Last commit on
  GitHub: August 2026, so a year of work sits unreleased.
- [poem-web/poem](https://github.com/poem-web/poem), about 4.4k stars, Apache-2.0. Roughly a
  fifth of the community of the other three.
- Tokio-based. Tower layers can be reused through the `tower-compat` feature.

### Hello World Example

```rust
use poem::{
    get, handler,
    listener::TcpListener,
    web::{Query, Json},
    Route, Server,
};
use serde::{Deserialize, Serialize};

#[derive(Serialize)]
struct HelloResponse {
    message: String,
}

#[derive(Deserialize)]
struct HelloParams {
    name: Option<String>,
}

#[handler]
async fn hello(Query(params): Query<HelloParams>) -> Json<HelloResponse> {
    let name = params.name.as_deref().unwrap_or("World");
    Json(HelloResponse {
        message: format!("Hello, {}!", name),
    })
}

#[tokio::main]
async fn main() -> Result<(), std::io::Error> {
    println!("Starting server at http://localhost:8080");

    let app = Route::new()
        .at("/hello", get(hello));

    Server::new(TcpListener::bind("127.0.0.1:8080"))
        .run(app)
        .await
}

// Usage:
// GET /hello -> {"message": "Hello, World!"}
// GET /hello?name=Diana -> {"message": "Hello, Diana!"}
```

### Ecosystem

Most of what Poem offers lives in the crate itself, behind cargo features. There is almost no
third-party layer around it, which cuts both ways: little to choose from, little to break.

| Need | Where | Notes |
|---|---|---|
| OAuth2 | `oauth2` plus a handler | No Poem-specific crate. `poem-openapi` only declares the scheme in the spec. |
| JWT | `jsonwebtoken` in a middleware | No Poem-specific crate. |
| Rate limiting | nothing built in | Not in `poem::middleware`. Write one, or put it in front of the process. |
| RBAC | roll your own | |
| CORS | `poem::middleware::Cors` | |
| CSRF | `poem::middleware::Csrf` | Feature `csrf`. |
| Sessions | `poem::session` | Feature `session`. |
| WebSockets | `poem::web::websocket` | Feature `websocket`. |
| SSE | `poem::web::sse` | Feature `sse`. |
| GraphQL | `async-graphql-poem` | |
| OpenAPI | `poem-openapi` | Derived from your types, the selling point. |
| Metrics | `poem::middleware::OpenTelemetryMetrics`, `TokioMetrics` | Features `opentelemetry`, `tokio-metrics`. |
| Tracing | `poem::middleware::Tracing`, `OpenTelemetryTracing` | |
| I18n | `poem::i18n` | Feature `i18n`. The only one of the four with this in core. |
| Static files | `poem::endpoint::StaticFilesEndpoint` | Feature `static-files`. Also `EmbeddedFilesEndpoint` for embedding. |

### Additional Examples

#### OpenAPI with Automatic Documentation

```rust
use poem_openapi::{OpenApi, Object, ApiResponse, payload::Json};

#[derive(Object)]
struct User {
    #[oai(example = "123")]
    id: String,
    #[oai(example = "John Doe")]
    name: String,
}

#[derive(ApiResponse)]
enum CreateUserResponse {
    #[oai(status = 200)]
    Ok(Json<User>),
    #[oai(status = 400)]
    BadRequest,
}

struct Api;

#[OpenApi]
impl Api {
    #[oai(path = "/users", method = "post")]
    async fn create_user(&self, user: Json<User>) -> CreateUserResponse {
        CreateUserResponse::Ok(user)
    }
}

// Automatically generates OpenAPI spec at /api-doc/openapi.json
```

## Picking one

None of the four is a bad choice. Rough decision rules, from the facts above rather than from
benchmark charts:

- **Axum** if you already live in the Tokio and Tower ecosystem, or expect to share middleware
  with `tonic` gRPC services. The price is `0.x` versioning: plan a migration at every minor bump.
- **Actix Web** if you want a major version that holds still and the widest choice of ready-made
  middleware. The 4.x line has been stable since 2022 and still ships several releases a year.
- **Rocket** if ergonomics and form handling matter more than release velocity. It is the slowest
  moving: 0.5.1 dates from May 2024, and the previous major from 2018.
- **Poem** if the OpenAPI document is the deliverable. `poem-openapi` derives it from your types,
  which none of the other three do without a separate crate. Smallest community by a wide margin,
  and releases are infrequent.
